## DP data behavior

- `Asset Detail → DP` calculates monthly depreciation as `Asset Value / Useful Life (years) / 12`.
- Accumulated Depreciation = Monthly Depreciation × depreciation periods; Net Book Value = Asset Value − Accumulated Depreciation. Accumulated Depreciation is capped at Asset Value.
- The mockup counts the depreciation start month as the first full period and calculates through the current month. It does not prorate partial months or model residual value / impairment.
- Useful life is read from the Asset Type master (`usefulLifeYears`). Asset value uses an explicit asset value when present, otherwise it sums the linked PO / PO Item value and scoped costs, adjusted by ordered quantity. PO-derived amounts are labeled as references. If no PO item value is linked, the DP form allows an Asset Value to be entered on the Asset record.
- `Enter DP details` / `Edit DP details` saves the depreciation start date. Useful life, monthly depreciation, accumulated depreciation, and net book value are calculated from the Asset Type, Asset Value, start date, and current month.
- When either Asset Value or the Asset Type useful life is missing, the monthly amount remains `Not recorded`.
- Implementation: `src/utils/depreciationUtils.js`, `src/components/AssetDepreciationDialog.jsx`, `src/components/AssetDetailDialog.jsx`, and `saveDepreciationDetails` in `src/App.jsx`.

## Lifecycle behavior

- Lifecycle activity is stored separately in local storage through `src/hooks/useAssetLifecycleStore.js`.
- Asset Detail supports Sub Asset, Modification, Maintenance, and Transfer entries. Transfer follows Requester Manager → Destination Department Leader → Asset Team Acknowledgement; assignment is updated only when the final step completes, with source/destination history retained.
- The `Approval` page separates Asset approvals and Movement approvals into tabs, each with its own pending count and search. Each Movement action advances the current step in sequence; the final Asset Team acknowledgement completes the request and updates the Asset assignment.
- The `Asset management → Movement asset` page opens prefilled with a sample Active Asset, destination line, serial number, photo filename, reason, and condition checks. Users can choose another Active Asset and the sample values update with it. Building, Location, and Line use select controls. The Transfer From/To pair contains only Building, Location, and Line; Department, Custodian, and Area stay as they were on the Asset record. Existing values in the Asset register are included alongside the asset master options. It creates a Transfer lifecycle request and uses the three approval steps above. Requests already pending approval are excluded from the selectable asset list to prevent overlapping transfers.
- Movement request records retain the source/destination assignment, reason, condition checks, entered serial number, and photo filename. The mockup records the selected file's name and type; it does not upload the image to a backend. The request and its approval progress appear in Asset Detail → Lifecycle.
- Sub Asset and Modification values above ฿50,000 are Capitalized; values at or below ฿50,000 are Expense. Maintenance does not automatically increase asset value. Spare Part history is displayed as a MIS reference; stock/issue remains in MIS.
- Main lifecycle UI: `src/components/AssetLifecycleDialog.jsx` and `src/components/AssetDetailDialog.jsx`.
- Movement request UI: `src/pages/AssetMovementPage.jsx`.
